# Task 1 Simulator - Health Data Detectives

## Overview
This project simulates daily step-count recovery trajectories for 365 days after knee surgery, including realistic individual variability and missingness.

## Requirements
- Python 3+
- numpy
- pandas
- matplotlib
- seaborn
- pyyaml
  
- RStudio 4.5+
- tidyverse

A `requirement.yaml` file is provided with version numbers

## Contents

- `synthetic_data.py`
  - R script for adding realistic missingness to the simulated trajectories

- `outputs/df.csv`
  - Final dataset containing simulated trajectories

- `missingness.R`
  - R script for adding realistic missingness to the simulated trajectories

- `trajectory_missingness_plot.png`
  - Visualisation of complete and observed trajectories

- `df_missing_final.rds`
  - Final dataset containing simulated missingness

## Run 
`python synthetic_data.py` followed by `Rscript missingness.R`: generate toy example
`python synthetic_data.py params.yaml` followed by `Rscript missingness.R`: simulate data according to specification in `params.yaml`

# Part 1: Simulating synthetic data and plotting trajectories

## Trajectory parameters

`params.yaml` contains the following trajectory defining parameters, which can be edited to reflect custom population

The simulator uses three trajectory groups with different recovery dynamics.

| Trajectory | n | ymax | t0 | k | noise | burn_in_time | optimum_time | Interpretation |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: | --- |
| 0 | 20 | 10000 | 100 | 0.1 | 400 | 42 | 365 | Blue Group / high final step count |
| 1 | 50 | 8000 | 140 | 0.1 | 400 | 42 | 999 | Green Group / moderate final step count |
| 2 | 30 | 6000 | 300 | 0.025 | 500 | 42 | 999 | Orange Group / lower final step count |

## Trajectory parameter definitions

| Parameter | Meaning |
| --- | --- |
| `n` | Number of simulated patients in this trajectory group |
| `ymax` | Maximum or plateau step count |
| `t0` | Mid point time of patient recovery |
| `k` | Growth rate / steepness of recovery |
| `noise` | Day-to-day random variation in steps |
| `burn_in_time` | Early post-op low-activity period |
| `optimum_time` | Length of time during which best recovery is maintained |


# Part 2: Missingness simulation

This section contains the missingness simulation pipeline developed for the HDD Hackathon trajectory analysis.

The underlying synthetic recovery trajectories were generated by previous section and `synthetic_data.py` and imported from:

`outputs/df.csv`

This workflow adds realistic wearable-device missingness patterns to the simulated trajectories.


## Missingness mechanisms

The simulation includes several realistic missingness mechanisms commonly observed in wearable-device studies:

1. Technical failure (MCAR)
   - Random isolated missing days independent of activity

2. Device non-wear
   - Increased missingness during weekends and low-activity days

3. Compliance decay
   - Increasing probability of missingness over follow-up time

4. Behavioural dropout (MNAR)
   - Longer periods of missingness among individuals with persistently low activity levels

### Follow-up duration

- `followup_days = 365`
  - Total duration of simulated follow-up in days.

### Technical failure (MCAR)

- `technical_failure_rate = 0.02`
  - Probability of random isolated missing days due to device malfunction or data loss.

### Device non-wear

- `base_nonwear_rate = 0.03`
  - Baseline probability of device non-wear.

- `weekend_extra_nonwear = 0.05`
  - Additional missingness probability during weekends.

- `low_steps_extra_nonwear = 0.08`
  - Additional missingness probability when daily step count is below the threshold.

- `low_steps_threshold = 3000`
  - Step-count threshold used to define low activity.

### Compliance decay

Compliance-related missingness increases over follow-up time.

- `compliance_prob_early = 0.02`
  - Missingness probability during days 0–99.

- `compliance_prob_mid = 0.06`
  - Missingness probability during days 100–199.

- `compliance_prob_late = 0.10`
  - Missingness probability during days 200–299.

- `compliance_prob_very_late = 0.20`
  - Missingness probability during days 300–365.

### Behavioural dropout (MNAR)

Longer periods of missingness associated with persistently low activity levels.

- `dropout_day_1 = 120`
  - First timepoint at which behavioural dropout may occur.

- `dropout_day_2 = 200`
  - Later follow-up stage associated with higher dropout probability.

- `dropout_prob_1 = 0.10`
  - Probability of behavioural dropout between days 120–199.

- `dropout_prob_2 = 0.30`
  - Probability of behavioural dropout after day 200.

- `dropout_gap_min = 14`
  - Minimum duration of a behavioural dropout gap in days.

- `dropout_gap_max = 35`
  - Maximum duration of a behavioural dropout gap in days.
